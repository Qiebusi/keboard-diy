# 键帽工坊 · Keycap Studio

一个纯前端的机械键盘**键帽设计与预览工具**。用户在键盘布局图上逐键设计键帽（底色、图例、图片贴图），可切换平面 / 3D 视图实时查看效果，并导出图片或保存工程文件。

纯前端，**Vite 5 + Vue 3 单文件组件**工程，构建产物是静态站点，可离线运行。

---

## 0. 运行与构建

```bash
npm install        # 安装依赖（vue@3.5 / three@0.147）
npm run dev        # 开发服务器 http://127.0.0.1:5188
npm run build      # 构建到 dist/
npm run preview    # 本地预览 dist/
```

- 端口固定 **5188**（见 `vite.config.js`），避免与本机其它 dev server 撞端口；
- 构建用相对路径（`base: "./"`），`dist/` 可直接丢到任意静态服务器或子目录；
- `npm run dev` 时控制台会挂 `window.__studio`（状态 + 动作）与 `window.__dbv` / `window.__dbs`（3D 视图实例）便于调试，生产构建不暴露。

## 2. 功能详述

### 2.1 键盘布局
- 内置四种布局：**60%（61 键）、75%（87 键）、TKL（87 键）、全尺寸（104 键）**。
- **导入 KLE**：支持 Keyboard Layout Editor 导出的 JSON 布局文件，导入后作为"KLE 自定义布局"出现在布局下拉框中。
- 切换布局时，已有设计会**自动迁移**：键名与尺寸相同的键帽保留原设计，其余用默认样式。
- 清空：一键恢复所有键帽为默认样式（迁移规则同样适用于恢复）。

### 2.2 单键设计（选中键帽后在右侧面板操作）
- **底色**：拾色器。
- **图例文字**：键帽上的字符，留空隐藏（如空格键）。
- **图例颜色**：拾色器 + "自动"按钮。自动模式按底色明暗选择深色或浅色文字，保证对比度。
- **图例大小**：0.5x ~ 1.8x。
- 默认样式：普通键帽浅灰白底、深色图例；修饰键（Shift、Enter 等宽键）灰底。
- **此设计应用到全部键**：把当前键的全部设计（含图片）复制到每一颗键（图例文字仍按各键默认值）。
- **重置此键**：恢复该键默认样式。

### 2.3 图片贴图
- **上传途径**（四种）：面板按钮选择文件、双击键帽、拖拽图片文件到画布、Ctrl+V 粘贴剪贴板图片。
- 支持格式：JPG / PNG / WebP。
- **变换调节**（滑条，且可联动手势）：
  - 缩放 0.2x ~ 4x（平面模式下在键帽上滚动滚轮直接缩放）；
  - 旋转 ±180°；
  - 水平 / 垂直位置偏移。
- **贴图范围**：
  - **仅顶面**：图片只铺在键帽顶面；
  - **十字展开包裹**：图片像"包纸"一样覆盖顶面并延伸到四个侧壁，图案在折缝处连续。
- **取模预览（十字展开）**：右侧面板内实时显示该键帽的真实十字展开图（纸样），即把键帽沿顶面四缘剪开、各壁绕自己的折缝摊平后的形状，展示顶面与四壁各分到图案的哪一部分；可在预览图上**直接拖拽移动原图**，3D 预览同步更新。
  - 纸样由 3D 几何的展开映射直接生成（同一份定义），尺寸按真实边长：顶面纵向为 `顶面深度 / cos(倾角)`；北/南壁外缘与折缝平行；**东/西壁的折缝是斜边，摊平后是斜楔形 —— 外缘不与折缝平行，臂高沿折缝变化**（倾角为 0 的 DSA / XDA 才是等高的梯形臂）。
- **移除图片**：一键去掉当前键的贴图。
- 替换新图片时保留当前贴图范围设置。

### 2.4 3D 预览
- **整盘 3D 视图**：拖拽旋转、滚轮缩放、单击选中键帽、双击上传图片、拖入图片。
- **单键 3D 预览卡片**：常驻显示当前选中键帽的 3D 模型，拖拽旋转、滚轮缩放；支持**放大**到全屏查看（Esc 或按钮退出）；可直接导出该键 3D 渲染图。
- **键帽高度档案**（3D 剖面造型，五种）：OEM（标准阶梯）、Cherry（原厂低矮）、SA（高球帽）、DSA（等高球帽）、XDA（等高平顶）。切换后整盘与单键模型立即重建；不同排的键帽高度与倾角不同，空格键使用专用造型。
- **键盘底板颜色**：即时生效。
- **分层拆解**：一键把整盘按层展开，像楼层一样自下而上看清每一层 —— 下壳 → PCB（热插拔轴座 / 卫星轴）→ 定位板 → 上盖边框 → 轴体 → 键帽；层间距（0.4x–2x）可调、**实时生效**，展开有缓动动画，切层间距 / 换键帽档案后保持展开状态。
- **分层显示开关**：六层各自可单独显示 / 隐藏（如藏起键帽看轴体、藏起下壳看腔体），隐藏的键帽不参与点选；「全部显示」一键还原。
- **外壳键位隔板**：沿口高度的一层外壳塑料 —— 键位区四周、以及布局里真正没有键的位置（留白 / 分组间隙，如 87 键 F 区与导航区的空档）都是外壳本体；**相邻键帽之间没有隔板**（开孔按键位合并，不会在键与键之间多出细条）。

### 2.5 全局键帽颜色
- 一键把**全部键帽底色**统一为指定颜色；不影响各键已设置的图例文字、图例颜色和图片贴图。

### 2.6 导出
| 导出项 | 内容 |
|---|---|
| 导出整盘 | 平面模式：整盘俯视图高清 PNG；3D 模式：当前 3D 视角截图 PNG |
| 导出当前键帽 | 选中键帽的高清俯视 PNG（含底色、图例、顶面贴图） |
| 单键 3D 导出 | 单键 3D 预览卡内的渲染图（放大状态下也可导出） |

导出的 PNG 不包含选中高亮等编辑态元素。

### 2.7 存档
- **自动存档**：所有修改即时自动保存到浏览器本地，刷新 / 重开页面自动恢复上次作品。
- **保存工程 / 载入工程**：下载或读取 `.json` 工程文件，可在不同设备间转移。
- **清空**：恢复全盘默认。

## 3. 数据规格

### 3.1 尺寸标准
- 键距标准：**1u = 19.05mm**。
- 键帽外框 = 键位格内缩 `gap`（每侧 0.5mm），顶面再按 `xi`（左右）/ `zi`（前后）内缩。
  三者都是**固定 mm 值**（不随键宽等比缩放），所以 OEM 1u 顶面 ≈ `0.643u × 0.738u`（左右 × 前后，前后比左右略深），空格等宽键的顶面 = 键宽 − 2×(gap + xi)。
- **平面与 3D 用同一套参数**：平面视图的外框、顶面矩形与 3D 模型的底环 / 顶环逐点同尺寸（此前平面用 `0.045u / 0.125u` 的近似值，横纵等量内缩，与 3D 有偏差）。

### 3.2 键帽高度档案（单位 mm，格式：[高度, 倾角°]）

| 档案 | F 排 | R1 数字排 | R2 Q 排 | R3 home 排 | R4 Z 排 | 底排 / 空格 |
|---|---|---|---|---|---|---|
| OEM | 11.2, 3 | 9.45, -1 | 9.0, -6 | 9.25, -9 | 9.25, -10 | 11.2, 3 |
| Cherry | 9.8, 0 | 9.8, 0 | 7.45, -2.5 | 6.55, -5 | 7.35, -11.5 | 7.35, -11.5 |
| SA | 14.89, 13 | 14.89, 13 | 12.925, 7 | 12.5, 0 | 12.925, -7 | 12.5, 0 |
| DSA | 8.1, 0（全排等高，含空格） | | | | | |
| XDA | 8.4, 0（全排等高，含空格） | | | | | |

数值取自 KeyV2（R1~R4 = row 1~4，F 排与底排/空格 = row 0/5），倾角按本表约定（正 = 前缘低）取反。
**空格与底排（空格键所在排）必须同规格**：OEM 的那一排是全板最高的 11.2mm（与 F 排等高），DSA / XDA 全排等高。

3D 造型与十字展开取模预览使用同一套档案数据，保证两者展开尺寸一致。

### 3.3 工程文件格式（.json）

```json
{
  "v": 1,
  "layoutName": "60",
  "customRows": null,
  "plateColor": "#23252f",
  "profile": "oem",
  "designs": {
    "0": { "bg": "#eef0f6", "legend": "Esc", "legendColor": null,
           "legendSize": 1, "img": null },
    "5": { "bg": "#ff8800", "legend": "5", "legendColor": null,
           "legendSize": 1,
           "img": { "data": "data:image/png;base64,...", "wrap": "net",
                    "scale": 1, "rot": 0, "ox": 0, "oy": 0 } }
  }
}
```

- `designs` 以键的下标为键；`img.data` 为图片的 dataURL（含 base64），因此含图工程文件可能较大。
- `legendColor: null` 表示自动配色。
- `img.wrap`：`"top"` 仅顶面，`"net"` 十字展开包裹。
- 载入时字段可缺失，缺失项用默认值补齐。

### 3.4 KLE 导入格式
- 接受 Keyboard Layout Editor 的标准 JSON：**二维数组**，字符串元素为 1u 键，对象元素为修饰（`{w, h, x, y, ...}`）；
- 也接受 `{ "keys": [...] }` 或 `{ "rows": [...] }` 包装形式。

## 5. 注意事项

- 图片以 base64 形式直接存入工程文件与本地存档，图片越多、越大，工程文件越大；自动存档有浏览器容量上限，超出时自动存档会静默跳过（手动"保存工程"不受影响，建议含大量图片时使用工程文件保存）。
- 十字展开包裹时，图案以**顶面为中心**向四壁延伸；要控制侧壁显示的内容，通过缩放与位置偏移调节，或在取模预览中直接拖拽。
- 取模预览的纸样是**真实展开**（等距摊平），不是投影：顶面四缘的纸样长度取真实边长，四壁绕折缝旋转摊平，故顶面有坡度时东/西壁必然是不平行的斜楔形。
- 贴图建议使用长宽比接近键帽顶面的图片；过小的图片会被放大到模糊。
- 布局切换与"应用到全部"均会保留图片（迁移按 键名+尺寸 匹配，未匹配到的键使用默认样式）。
- 刷新页面即恢复自动存档；"清空"只重置设计，不清浏览器存档，可在清空后再修改并自动保存新状态。
